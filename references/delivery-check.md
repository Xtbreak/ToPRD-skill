# 交付检查

交付前检查所有被用户请求的产物，发现问题先查材料或问用户，再修正文档。

- PRD 保留约定七节，场景、范围、用户流程、功能、评测、验收和交付计划形成闭环。
- 核心功能有稳定 FR 编号，相关实现和面试题使用相同编号。
- 用户的范围、数字、条件、取舍、项目阶段和贡献归属得到保留。
- 缺失信息已通过对话解决。正文没有“待确认”“待填写”、占位符、填写指导、未回答问题、对话记录或无关建议。
- 已获用户确认的未评测、未实测和缺少线上数据状态在相关位置加粗显示。
- 规划与实际实现分别表达。代码存在不代表已部署，单次试跑不代表正式评测。
- 模型选型和项目指标有证据，指标定义和通过门槛能够对应。未评测情况下没有伪造分数或宣称达标。
- 功能验收、AI 通过门槛和上线效果分别描述，重要失败分支有处理规则。
- 额外文档有用户选择或此前授权。默认产物数量为一份。
- 项目详解解释了实际流程、实现和取舍。面试题经过项目化改写，回答和追问有事实支撑。
- Markdown 表格和图可读，引用可访问，敏感信息未进入文档。交付文件只包含正式项目内容。

检查完成后在聊天中给文件链接和简洁交付说明，文档正文不追加本清单。
