# 项目实现详解

用户选择此文档后生成独立 `项目实现详解.md`。定位是帮助用户理解项目、解释技术取舍。与 PRD 共用 FR 编号，结合项目代码或明确批准的方案撰写。

## 正文结构

1. 项目全貌。说明用户任务、项目阶段、实现版本及整体输入输出。
2. 整体架构。用架构图描述界面、业务逻辑、模型、工具、数据和外部服务，解释各部分为什么存在。按实际项目取舍模块。
3. 核心请求流程。沿一次真实输入追踪到输出，说明每一步读写的数据、调用和状态；给出成功路径、失败路径及用户接管位置。
4. 功能实现。逐条对应核心 FR，写入口、实现模块、关键规则、数据结构、权限与异常处理。代码位置和专业概念解释放在相应段落。
5. 模型、提示词与数据。解释选型、模型收到的信息、上下文、知识库、工具调用或记忆如何配合。只展开项目实际涉及的能力。
6. 方案取舍。比较实际考虑过的方案，说明约束、决定、代价及证据。没有历史决策记录时直接问用户。当前可推导的技术解释不可冒充当时的选型过程。
7. 评测、问题与优化。讲清测法、结果、具体失败案例、定位过程、改动和复测依据。未做的项目环节按确认状态加粗标明。
8. 个人贡献与协作。记录用户、同伴、开源组件及 AI 编程工具的实际贡献。询问用户负责的需求、判断、实现或验证工作，并保留核心含义润色。

## 写法

先用直白语言说明用途，再结合本项目解释机制和取舍。必要的技术细节要能支撑“为什么这样做”“失败发生在哪里”的追问。不要复制整段源码或塞入无关术语。

规划项目在标题或页首注明“实现方案”，使用计划时态。实际完成后再依据代码和验证记录更新实现部分。每条性能或业务结果要有真实统计口径。

完整面试问答按另一份文档交付；用户同时选择时，用功能编号和章节引用建立联系。
