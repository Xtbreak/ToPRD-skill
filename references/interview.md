# 项目面试问答

用户选择后生成独立 `项目面试问答.md`。可以直接依据项目和用户回答完成，无需先生成实现详解。

## 生成过程

1. 阅读 PRD、已提供的实现材料及用户经历，确定项目阶段、角色和实际贡献。
2. 根据真实项目选择问题方向，围绕关键功能、决策、失败案例和结果改写题目。
3. 历史原因、本人职责和成绩无证据时直接询问用户，取得回答后润色。
4. 每题写简洁口述回答，再展开 2—3 层追问及回答，全部关联具体实现或真实经历。

## 问题方向

| 方向 | 可按项目改写的问题 |
|---|---|
| 用户价值 | 问题怎么发现？已有办法有什么不足？为什么需要 AI？ |
| 范围取舍 | 首版为什么选这些场景？延后了什么？有什么依据？ |
| 模型和方案 | 比较过哪些方案？质量、成本、速度分别怎么量化和取舍？ |
| 实现流程 | 一次请求经过哪些步骤？模型、工具和业务规则分别负责什么？ |
| 数据和知识 | 来源如何获得？更新如何生效？错误或缺失如何处理？ |
| 评测 | 样本如何选？谁判分？指标分子分母是什么？为什么采用这个门槛？ |
| 失败和优化 | 具体坏例是什么？如何定位原因？改完怎么验证改善？ |
| 上线效果 | 谁实际使用？效果如何统计？离线表现和线上使用有何差异？ |
| 协作和贡献 | 本人做了什么决定和工作？与研发或 AI 工具怎么分工？ |
| 迁移与复盘 | 规模、预算或模型变化时如何调整？重做会改哪里？ |

按项目触发深入问题。知识库问答涉及解析、切分、检索、引用和生成错误定位；Agent 涉及工具选择、权限、重试和人工接管；生成图片涉及质量、一致性、可控性和成本；其他项目按实际机制生成。反事实问题可以讨论未采用的方案，但回答明确属于假设分析。

## 每题结构

- 项目化问题。
- 考察点，用一两句话解释。
- 口述回答，先给结论，再说明背景、本人行动、理由和真实结果；按题目裁剪。
- 连续追问及对应回答，每层围绕上一层的具体决策或证据深入。
- 回答依据，指向 FR、代码、评测记录或用户提供的经历。

从规划阶段产出的答案使用计划时态。用户确认 **当前未做评测** 时，回答应解释实际进度与已经确认的评测设计。案例、数据、项目规模和本人贡献均须真实。

## 题型来源

以下是面试准备方向的参考，不据此声称问题是某公司必考题或给出精确出现频次。面向特定岗位时，读取用户提供的 JD；需要新资料时检索公开面试指南，记录来源。技术原理核对官方文档、源码或论文。

- [Aced AI Product Manager Interview Questions](https://www.aced.io/blog/ai-product-manager-interview-questions)，用于 AI 产品判断、模型、评测与取舍题型。
- [CZI Product Management Interview Guide](https://chanzuckerberg.com/wp-content/uploads/sites/8/2025/02/Product-Management-Interview-Guide.pdf)，招聘方公开指南，用于产品思考、执行及跨团队协作方向。
